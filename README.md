## 通信协议：13 字节

所有链路（无线、板间串口）都是 13 字节定长帧：**byte 0 = 0x55，byte 12 = 0xFF**，其余按用途分配。**不加 CRC、不加序号**——无线侧已有 nRF24L01 的 16 位硬件 CRC，板间串口是短距离点对点，帧完整性只靠首尾两个字节。这是设计选择，不是遗漏。

同一组 13 字节有三种用法，区别只在 byte 8..11：

### 1. 无线帧：遥控器 → 底盘 / 云台 / 发射 / 灯条

| 字节 | 字段 | 含义 |
| :---: | :--- | :--- |
| 0 | 0x55 | 帧头 |
| 1 | key | 8 个按键，低有效；bit0 自旋/跟随，bit1 激光，bit3 阵营，bit4/5 供弹/退弹 |
| 2 | enl | 左旋钮 0..127，小陀螺转速 |
| 3 | enr | 右旋钮 0..127，摩擦轮转速 |
| 4-5 | lx | 左摇杆 X，**已积分**为角度，rad×100 |
| 6-7 | ly | 左摇杆 Y，**已积分**为角度，rad×1000 |
| 8-9 | rx | 右摇杆 X，±127 |
| 10-11 | ry | 右摇杆 Y，±127 |
| 12 | 0xFF | 帧尾 |

### 2. FOC 帧：底盘 → Yaw 板，云台 → Pitch 板

FOC 板用不到底盘平移速度，所以 8..11 换成发送方自己的状态：

| 字节 | 字段 | 含义 |
| :---: | :--- | :--- |
| 1..7 | 同无线帧 | 按键、旋钮、左摇杆（原样转发） |
| 8-9 | att | 发送方姿态：底盘 Yaw / 云台 Pitch，rad×100 |
| 10-11 | cmd | 轴指令，rad×100（Pitch 绝对角，Yaw 增量） |
| 12 | 0xFF | 帧尾 |

### 3. 回发帧：Yaw / Pitch → 底盘 / 云台

| 字节 | 字段 | 含义 |
| :---: | :--- | :--- |
| 0 | 0x55 | 帧头 |
| 1-2 | ang | 实测轴角，rad×100 |
| 3..11 | — | 保留，置 0 |
| 12 | 0xFF | 帧尾 |

16 位字段一律大端、有符号。

## 本版改动

- **全车统一 13 字节帧**：遥控器、底盘、云台、发射、灯条、两块 FOC 板全部改用同一套 `frame13.h` 定义；无线空口负载从 32 字节（只填 13 字节有效内容）改为真正的 13 字节。
- **修正右摇杆映射**：满杆原本映射到 126（用 128 做分母，白丢一个 count），接收端又是 int8_t，任何超过 127 的值都会变成负数。现在钳到 ±127 并用 127 做满量程，满杆正好 ±127。
- **统一 FOC 命令字段的标度**：旧代码在无 IMU 时把 0.001 LSB 的 ly 原样透传，而 Pitch 板按 1/1000 解码、底盘侧按 1/100 编码，命令偏小 10 倍。现在命令字段固定为 rad×100。
- **源码统一 UTF-8**：仓库里原本混有 GBK 文件，GitHub 上中文注释显示为乱码，已全部转换（少量早期被错误转码的注释无法还原，保留为 `�`）。
- 移除编辑器/AI 工具残留（`.claude`、`.zcode`）与空文件。

## 已知限制

- 帧只有首尾校验，没有 CRC 和序号；丢包检测依赖上层超时（底盘 100 ms、FOC 板 100 ms）。
- Pitch 轴在无 IMU 时的指令方向与标度需要在台架上再确认一次（代码里保留了说明）。
